# This is deliberately NOT `pip install -r backend/requirements.txt`. Two real,
# reproduced blockers make the full file uninstallable on a clean environment
# (verified with a single `pip install -r requirements.txt` on 2026-08-30):
#
#   1. `emergentintegrations==0.1.0` (requirements.txt:26) is a private package,
#      not published on PyPI ("No matching distribution found"). It is a real
#      runtime dependency of backend/services/webhook.py:8 (Stripe checkout
#      integration) — not dead code — so it cannot simply be deleted from
#      requirements.txt without breaking that feature.
#   2. `cryptography==46.0.4` (requirements.txt:20) conflicts with
#      `webauthn==3.0.0` (requirements.txt:144), which requires
#      `cryptography>=49.0.0`. pip's resolver reports this directly:
#        "webauthn 3.0.0 depends on cryptography>=49.0.0"
#      This is an internal inconsistency in requirements.txt itself, not an
#      artifact of this file — it reproduces on a clean resolver.
#

# in backend/requirements.txt itself (cryptography bumped to 49.0.0; the

# no longer blocks importing the app). `pip install -r backend/requirements.txt`
# (minus the one still-private emergentintegrations line) now works on a clean
# environment — verified there. This file still exists because GitHub Actions'
# runner has no access to the private index either, same as this session's
# sandbox, so CI still needs a curated, fully-public-PyPI subset.
#
# This file instead pins the exact set proven (by running the real test
# suite in this repo) to be necessary and sufficient to:
